# AI Voice Receptionist SaaS

A production-oriented, multi-tenant B2B SaaS platform that provides AI-powered voice receptionists for small businesses.

The platform is operated and managed by a single platform operator/agency. Businesses receive an AI receptionist capable of handling customer conversations, collecting lead information, checking appointment availability, booking appointments, and maintaining customer/call records.

## Overview

The system is designed for small businesses with approximately 3–7 employees in the United States, United Kingdom, and European Union.

Initial supported industries:

* HVAC
* Cleaning Services
* Dental Clinics

The platform combines:

* Next.js
* TypeScript
* Supabase
* PostgreSQL
* Gemini AI
* Gemini Live
* Server-side AI tools
* Role-based access control
* Row Level Security
* Multi-tenant business isolation
* Appointment scheduling
* Voice session management
* Automated stale-session cleanup

## AI Tool Architecture

The AI communicates with the application through controlled server-side tools.

Available tools include:

1. `getBusinessInformation`
2. `getServices`
3. `searchKnowledgeBase`
4. `findCustomer`
5. `createCustomer`
6. `updateCustomer`
7. `createLead`
8. `checkAvailability`
9. `bookAppointment`
10. `saveCall`

The general flow is:

```text
Customer
   ↓
AI Voice Receptionist
   ↓
Gemini Live
   ↓
Server-side AI Tool Endpoint
   ↓
Authorization + Validation
   ↓
Business Context
   ↓
Supabase / PostgreSQL
   ↓
Result returned to AI
```

The browser never directly controls protected business operations.

## Voice Architecture

Voice conversations use Gemini Live.

The general session flow is:

```text
Client / Voice Interface
        ↓
Create Voice Session
        ↓
Request Secure Gemini Token
        ↓
Gemini Live Connection
        ↓
AI Conversation
        ↓
Server-side Tool Calls
        ↓
Voice Session State
        ↓
Finalize Session
        ↓
Call Record + Related Data
```

Gemini API credentials remain server-side.

Short-lived Gemini credentials are generated by the server rather than exposing the permanent API key to the browser.

## Multi-Tenant Security

Tenant isolation is a core architectural requirement.

Every business-owned record contains a `business_id` where appropriate.

Examples include:

* customers
* leads
* calls
* appointments
* services
* knowledge base records
* voice sessions

### Platform Admin

`PLATFORM_ADMIN` users can operate across businesses, but AI/API business context must be explicitly supplied.

The server verifies that the selected business exists before allowing the operation.

### Client User

`CLIENT_USER` users are permanently associated with one business.

The server derives their business from the authenticated profile rather than trusting a frontend-supplied business ID.

A client user attempting to access another business is rejected.

### Database Protection

Supabase Row Level Security provides an additional database-level security boundary.

Application-level authorization and database-level RLS are both used.

## Appointment Scheduling

Appointment times are stored in UTC.

Business-local times are calculated using the business's configured IANA timezone.

For example:

```text
Business timezone
        ↓
Customer requested local time
        ↓
Validate business hours
        ↓
Calculate service duration
        ↓
Check conflicts
        ↓
Convert to UTC
        ↓
Store appointment
```

Service duration is retrieved from the database.

The AI does not provide or control appointment duration.

The database also contains an exclusion constraint to protect against overlapping appointments during concurrent booking attempts.

---

## Phone Number Handling

Customer phone numbers are normalized and validated before being stored.

The system uses `libphonenumber-js` to convert valid numbers into E.164 format.

Example:

```text
212-555-0123
        ↓
+12125550123
```

Business country information is used when resolving phone numbers.

## Cron Session Cleanup

The application contains a protected endpoint for cleaning stale voice sessions:

```text
/api/ai/live/session/cleanup
```

The endpoint requires:

```text
Authorization: Bearer <CRON_SECRET>
```

It uses the Supabase service-role client server-side.

Active voice sessions older than the configured stale-session threshold are marked as failed.

Vercel cron is configured to execute the cleanup endpoint every 15 minutes.

Configuration:

```text
vercel.json
```

The cron secret must be configured as:

```env
CRON_SECRET=
```

in the production deployment environment.

## Important Design Principles

### Server Is the Source of Truth

The browser and AI are not trusted to determine:

* Business ownership
* User role
* Appointment availability
* Appointment duration
* Booking status
* Service ownership
* Customer ownership
* Lead ownership
* Business hours
* Protected configuration

These are validated server-side.

### AI Is Not the Database

Gemini is responsible for conversation and reasoning.

The application is responsible for authoritative business operations.

```text
Gemini
= conversation + reasoning

Application
= authorization + validation + business logic

PostgreSQL
= persistent source of truth
```

### Multi-Tenancy Is Enforced at Multiple Layers

Tenant isolation is not dependent solely on frontend behavior.

It is protected through:

```text
Authentication
      +
Server authorization
      +
Business context validation
      +
Supabase RLS
      +
Database constraints
```

## Security Notes

Never commit:

```text
.env.local
.env
Supabase service-role keys
Gemini API keys
Cron secrets
```

The repository intentionally ignores environment files while keeping:

```text
.env.example
```

available as a configuration template.

Never place the Supabase service-role key or Gemini API key inside a `NEXT_PUBLIC_*` variable.

Never trust a frontend-provided business ID for client-user authorization.

Never confirm an appointment unless the server-side booking operation succeeds.

Never allow the AI to invent service prices, appointment availability, appointment durations, or business policies.
